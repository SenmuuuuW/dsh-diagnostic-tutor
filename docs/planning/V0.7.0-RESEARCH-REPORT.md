# v0.7.0 Dynamic Lesson Engine — research report

Date: 2026-11-06. Branch: `research/dynamic-lesson-engine`, based on
`release/0.6.0` (`df1c858`). This is a research spike, not production.

## 1. Question

> Can an AI model reliably generate safe, correct and useful interactive
> educational animations from a declarative scene specification?

The answer from this run is **mixed**:

- safe declarative scenes can be generated and rendered;
- first-pass reliability is low without schema feedback and repair;
- after bounded schema-repair the model reached a renderable scene for all 20
  cases;
- five CS cases required a **full rewrite**, not a local field repair, because
  the model used a different state-machine timeline shape;
- 20 rendered scenes is **not** evidence of 20 successful lessons. Educational
  quality was manually reviewed, not measured with learners.

## 3. What was built

### SceneSpec v0

A bounded declarative schema with viewport, metadata, properties, six primitive
types (`rect`, `circle`, `line`, `path`, `text`, `arrow`), a finite timeline,
keyframes/easing, controls, checkpoints, narration, accessibility, fallback and
source refs. Numeric fields can be finite numbers or bounded arithmetic
expressions. See [`V0.7.0-SCENE-SPEC.md`](./V0.7.0-SCENE-SPEC.md) and
[`SCHEMA.md`](../../research/dynamic-lesson-engine/SCHEMA.md).

### Safe interpreter

`research/dynamic-lesson-engine/scene-spec.mjs` validates structure and
semantics without executing code. `renderer.mjs` builds SVG with
`createElementNS` and `textContent`, uses deterministic explicit time, finite
animation, checked attributes, and a static fallback. No eval, Function, HTML,
CSS, URLs, event handlers, foreignObject, images or remote assets.

### Browser Scene Lab

`preview/scene-lab/` is a standalone research page served by the existing
preview server. It supports JSON load/validation/render, play/pause/replay,
seek, step, parameter sliders, checkpoint jumps, narration, fallback, metrics,
keyboard controls and reduced-motion fallback. It is not imported by the
production plugin bundle.

## 4. AI generation experiment

### Method

- Model: **DeepSeek-V4.1-Flash** via DSH `0.2.2-rc.1` in an isolated `DSH_HOME`.
- 20 cases across math, physics, CS, economics and statistics.
- Prompts described the learning case and the schema; the model used real
  `write` tools to save JSON files.
- The model's first output was kept as `attempt1`. Invalid output received
  structured validation errors and was regenerated by the model.
- No human edited the JSON attempts; no fixture is counted as AI generation.
- Batches were used to reduce prompt overhead; the per-case prompt text is in
  `research/dynamic-lesson-engine/benchmark/prompts/`.
- A limited schema-compatibility revision (IDs/case/aliases/defaults) was made
  during the spike and is documented; raw first-pass numbers are reported
  separately from the revised-schema numbers.

The first-pass failures were not hidden. The strict original failures include:

- `accessibility.alt` over 300 characters (3 math cases);
- bare expression strings instead of `{expr}` wrappers (4 physics cases);
- case-mismatched property variable (`testx` vs `testX`, electric field);
- different control/checkpoint/reducedMotion shapes (5 economics/statistics
  cases);
- a completely different state-machine timeline shape with no primitive IDs
  (5 CS cases; full rewrite needed).

## 5. Failure analysis

### Schema/reliability failures

The dominant failure is not unsafe output; it is **schema shape drift**:

- models naturally wrote bare arithmetic strings (`"x2": "180 + ..."`);
- models omitted wrapper objects and used `t` instead of `at` in CS timelines;
- models used `type/target` controls and boolean reduced-motion;
- property identifiers were written with inconsistent case;
- CS concepts pulled the model toward a state-machine description that the
  primitive timeline cannot represent.

The repair loop was effective for local failures (12/12), including the CS
full rewrite. But repairs consume extra model turns and are not free: the
first-pass rate must be treated as a reliability metric, not hidden by the
final 20/20.

### Safety failures

None in the browser safety suite:

- event-handler key, `url()` fill and script-in-path were rejected before
  render;
- 121 primitives and 101 keyframes per track were rejected;
- malicious/stress specs produced no `<script>`, no `foreignObject`, no event
  attributes, no external links and no external network requests;
- 120-primitive stress scene rendered 121 nodes at 1.1 ms in one frame;
- `prefers-reduced-motion: reduce` produced a static fallback and disabled
  autoplay;
- seek to the same time twice produced identical SVG;
- Space played, ArrowRight stepped, checkpoint click paused at the checkpoint.

### Educational failures/risks

- CS scenes are compressed: bubble sort uses only three values; recursion is
  text-heavy; these are **medium**, not high, quality.
- Several scenes encode distinctions with color (red/green/blue), although most
  also have labels. This is a partial accessibility failure for color-vision
  deficiency and screen-reader users.
- Overlapping labels and dense layouts appeared in generated scenes.
- No generated scene was tested with a learner. "Correct by inspection" is not
  "teaches effectively".

## 6. Performance

Measured in the real Scene Lab:

- per-scene final render: 0.0–0.8 ms in the recorded frame; 15–60 SVG nodes;
- stress scene: 120 primitives, 121 nodes, 1.10 ms initial frame;
- 2-second play: 123 rAF frames / 2.21 s ≈ **55.7 fps**;
- heap delta during the stress play: ~**88 KB** in this run (not a memory
  guarantee);
- timeline durations: 4.5–20 s; no infinite loop; no timers after pause/end.

These measurements are for the prototype, not production Study overhead.

## 7. DSH synchronization and immersive workspace findings

Content-embedded cues (narration/checkpoints/pause/resume) are proven in the
prototype. The host does **not** currently provide a documented browser-side
typed teaching-event stream. Raw `agent/assistant-stream` is a host runtime
event; it is not a semantic scene cue API.

The existing plugin can already make Study cover the right-sidebar viewport via
`ctx.layout.openRightbar(track, fullscreen)` and host the lesson in a session tab.
It cannot safely implement a general immersive workspace, browser-back scene
history, focus trapping, or host-restored scene state without host changes.
Details and proposed APIs are in
[`DSH-IMMERSIVE-LEARNING-WORKSPACE.md`](./DSH-IMMERSIVE-LEARNING-WORKSPACE.md).

## 8. Go / No-Go

### General production Dynamic Lesson Engine: **No-Go**

Do not ship an open-ended "any topic → generated animation" production engine
on this evidence.

Blockers:

1. **40% reviewed first-pass**; 12/20 required repair, including 5/5 CS full
   rewrites. That is too fragile for an unattended Tutor loop.
2. **No learner outcome evidence.** 20 rendered scenes and manual review cannot
   substitute for comprehension/transfer testing.
3. **No host-level teaching event/back/focus/surface-state API.** Tutor
   synchronization cannot be built honestly inside the current plugin contract.
4. **Accessibility is partial.** Alt/keyboard/reduced-motion exist, but color
   reliance, label overlap, and no live scene narration for screen readers.
5. **Schema/teaching correctness is not machine-proven.** Manual review found no
   conceptual errors in 20 samples, but generated formulas and evidence
   boundaries still need a verifier/curated constraints.

### Constrained v0.8.0 Engine v1: **Conditional Go**

A narrow next phase is justified because the safe core works and the browser
renderer is reliable. Recommended minimal scope:

1. Keep SceneSpec research-only until a production `scene` block is reviewed;
   then add **one** additive block type with static fallback and no arbitrary
   code.
2. Render only **curated/reviewed** specs in production. Do not let the Tutor
   generate an arbitrary spec and render it unreviewed.
3. Use content-embedded cues only. Do not claim Tutor synchronization until the
   host exposes typed semantic events (G4 in the immersive requirements).
4. Persist timeline/parameter/checkpoint state in Study progress; do not rely on
   tab remount to preserve it.
5. Add a learner study (comprehension and transfer) before calling any scene
   pedagogically effective.
6. Keep the shell surface within the current rightbar fullscreen contract; do not
   patch host CSS or capture browser Back globally.
7. Target a measurable reliability bar before expanding: e.g. ≥70% first-pass
   validity on a fixed 20-case suite and ≥90% after one repair, with a human
   review gate for every production scene.
