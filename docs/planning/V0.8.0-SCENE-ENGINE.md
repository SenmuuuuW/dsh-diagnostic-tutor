# v0.8.0 Production Scene Engine v1

Status: development branch `feat/v0.8.0-scene-engine`. **Not published.** This is
a conservative playback feature, not permission to auto-generate scenes for users.

## What shipped

- A new additive `scene` lesson block.
- A bounded SVG player for approved scenes, embedded in the existing Study
  surface (not a parallel course system).
- A default-off feature flag.
- A code-reviewed approval registry keyed by a canonical digest.
- Presentation-only scene progress in the existing `CourseAttempt.study` record.
- Static fallback whenever the flag is off, the scene is not approved, the spec
  fails validation, or rendering fails.

No `scene` block is imported by the v0.6/production release branch. No AI
generation tool or production generation flag exists.

## Scene block

```json
{
  "id": "scene-unit-circle",
  "type": "scene",
  "content": {
    "sceneVersion": "1",
    "spec": { "version": "0.1", "...": "reviewed SceneSpec" },
    "fallback": "A unit circle with a point and a dashed height..."
  },
  "sourceRefs": []
}
```

`SceneBlockContentSchema`:
- `sceneVersion` must be `"1"`;
- `spec` must validate against the bounded SceneSpec runtime;
- `fallback` is mandatory (1–2000 chars);
- unknown envelope keys are rejected;
- the encoded spec is capped at 131,072 chars;
- known lesson caps still apply (24 blocks / 262,144 bytes).

The block is additive in the 15-type vocabulary. Old lessons parse unchanged;
old clients see an unknown block by type and keep their normal fallback. The block
does not alter existing block semantics.

## Renderer

`src/client/scene-player.tsx` renders only after validation and approval:
- six primitives: rect, circle, line, path, text, arrow;
- deterministic time with finite duration;
- keyframes/easing, numeric property sliders, checkpoints, narration;
- play/pause/replay/seek/step ±0.5s;
- static fallback and bilingual labels;
- keyboard-operable native controls;
- `prefers-reduced-motion` note; playback never autostarts;
- no eval/Function, no HTML/CSS injection, no URLs, no event attributes,
  no `foreignObject`, no external images.

The approved registry's current scene is hand-authored and reviewed. The
v0.7 AI-generated scenes are **not** approved for production.

## Feature flag

```bash
DSH_DIAGNOSTIC_TUTOR_DYNAMIC_SCENES=1
```

Default: **off**. When off:
- the browser receives `{dynamicScenes:{enabled:false}}` from
  `GET /diagnostic-tutor/api/scene-config`;
- existing scene blocks show their static fallback;
- model tools refuse new scene writes with `dynamic-scenes-disabled`.

There is **no** `aiSceneGeneration` production flag. Generation remains the
research pipeline under `research/dynamic-lesson-engine/v2/`.

## Approval boundary

`src/scene/approved.ts` is the approved registry. Approval requires a reviewed
exact pair `{spec, fallback}`; the canonical key is hashed with SHA-256 by
`src/scene/approval.ts` and checked by the tool write boundary. The renderer also
checks the same code-reviewed registry in the browser.

To approve a new scene:
1. add the scene to `APPROVED_SCENES` in source;
2. review it in Scene Lab and run accessibility checks;
3. add/adjust tests for its exact digest and fallback;
4. commit the source review.

A model cannot set an `approved` field. Changing any spec byte, fallback text, or
top-level field changes the canonical key and invalidates approval. The tool
refuses unapproved content even when the feature flag is on. All content is
still runtime-validated, so approval never substitutes for validation.

## Study persistence

`CourseAttempt.study` gains an optional `scenes` record keyed by stable block id:

```ts
{
  blockId, sceneHash, time, params, playing, checkpointId?, reached
}
```

`sceneHash` is a deterministic fingerprint of `{spec,fallback}`. A changed spec
invalidates old progress. Restored playback always starts paused; it does not
autoplay. The existing `stepIndex`, `scrollRatio`, `fullscreen` and `finished`
fields are unchanged; old records without `scenes` keep opening.

Scene progress is presentation state only. It never creates evidence, changes a
knowledge node, submits an answer, calls the tutor, advances a route, or marks
lesson completion. Scene playback completion does not enable/finish the lesson;
the learner must still press Continue.

The save path drops scene entries that do not point to an actual scene block in
that lesson.

## Study integration

- The scene is a normal block inside the existing `StudySession` / `LessonBody`.
- Works in side-panel and full-screen Study because it uses the existing
  right-sidebar full-screen mode.
- Continue/Back operate on the existing Study step state.
- Leaving/re-entering restores the persisted scene position if the fingerprint
  matches; otherwise the scene resets to 0, paused.
- Missing approval/flag/validation uses the static fallback in place.

## Known limitations

- The production renderer intentionally supports only the reviewed v0 SceneSpec
  subset; the research named-state extension is **not** accepted in production.
- No approved-scene CMS or remote registry; approval is a code review.
- The current approved catalog has one scene. It proves the boundary, not a
  content library.
- No typed tutor→scene synchronization (v0.9 host work).
- Scene progress is local to the plugin store, not cross-device.
- AI generation is not production-ready: see [`V0.8.0-GENERATION-V2.md`](V0.8.0-GENERATION-V2.md).
