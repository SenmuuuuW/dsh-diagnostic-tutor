# v0.8.0 AI Scene Generation v2 (research)

Status: research branch only. Not a production generation feature. The
production player accepts only code-approved scenes; this report does **not**
claim that AI output is automatically safe or pedagogically correct.

## Pipeline

```
Teaching case
  → compact plan (representation, entities, motion, controls, checkpoints,
    misconception test, accessibility)
  → SceneSpec generation
  → strict validator (structure + limits + expressions + state refs)
  → browser Scene Lab render
  → bounded repair (one repair turn per failed artifact)
  → manual review
```

Research artifacts:
- [`v2/batch-prompt.mjs`](../../research/dynamic-lesson-engine/v2/batch-prompt.mjs)
  — plan + exact contract for real-model batches;
- [`v2/prompt.mjs`](../../research/dynamic-lesson-engine/v2/prompt.mjs) —
  separate plan and single-case prompts;
- [`v2/cases-holdout.json`](../../research/dynamic-lesson-engine/v2/cases-holdout.json)
  — 10 holdout cases created before the holdout run;
- `v2/generated/` — raw final scenes and plans;
- `v2/raw/` — preserved first attempts and the prompt-iteration failure;
- `v2/results/summary.json` — machine-readable metrics and manual review.

## Prompt iterations (not hidden)

The research started from the v0.7 schema and added a bounded named-state
extension for algorithm scenes (`states` + `stateTimeline` with primitive
property overrides).

Prompt v2a (used for the first math batch) failed all 5 cases because the model
put instructions in `checkpoints[].learnerAction`; the schema correctly accepted
only `continue|answer`. Those attempts are retained under
`research/dynamic-lesson-engine/v2/raw/prompt-a-regression/`.

Prompt v2b added:
- explicit learnerAction enum and "put instructions in body";
- explicit easing enum (`linear|ease-in|ease-out|ease-in-out|step`);
- explicit named-state cap (12 states, 120 overrides);
- exact target/keyframe contracts.

After v2b, regression first pass was **14/20**: math 5/5, physics 5/5, CS 4/5,
economics/statistics 0/5 (the model used `easeInOut`). The one graph failure had
13 named states, over the cap. All six failures were repaired by one model repair
turn (6/6), yielding 20/20 valid. The prompt was not changed again before the
holdout.

Prompt v2c (final holdout prompt) includes those fixes. The 10 holdout cases were
created before the holdout run and were **not** iterated on; first-pass was
**10/10**.

| Manual review: medium | 5 | **3** | **2** |

The v0.7 and v0.8 numbers are **not directly comparable**:
- v0.8 schema adds the research named-state extension;
- v0.8 prompts are different and include explicit contracts;
- v0.7 final outputs were produced by a different batch/repair protocol.
The honest comparison is directional: explicit planning + exact contract +
bounded repair improved first-pass schema validity substantially on this suite.

## The critical failure: valid and rendered ≠ teachable

Four v2 math scenes passed the schema and rendered in the browser, but were
**not visually reviewable**:
- the unit circle had no explicit fill/stroke and rendered as a black disc;
- gradient/derivative curves lacked visible strokes and were effectively blank;
- some matrix elements were not legible.

This is exactly why "browser render success" is not "teaching success". The
renderer is reliable; the prompt did not require every primitive to declare its
visible style. The v0.8 holdout scenes mostly did include explicit styles, but
the regression set still contains these failures. They are counted as low /
not-reviewable rather than silently removed.

**Do not approve or ship an AI-generated scene just because it renders.** The
production approved registry contains a hand-authored, manually reviewed scene;
none of the v2 AI scenes are in it.

## Targets

| Target | Result |
| --- | --- |
| Regression first strict valid ≥70% | **70%** (14/20) |
| After one repair ≥90% | **100%** (20/20; 6/6 repaired) |
| Browser render ≥95% | **100%** (30/30) |
| No major security violation | **pass** (validator tests + browser injection cases) |
| Holdout does not collapse | **10/10 first pass** |
| Human review required | **yes**, 4 not-reviewable, 5 medium, 4 low |
| Learning effectiveness | **not tested** |

## Cost / time

The model calls ran in the isolated DSH profile. Exact per-case token accounting
was not reliably exported; the DSH session displayed token usage in the
hundreds of thousands for multi-case batches. Generation wall time was several
minutes per 5-case batch and is not a production SLA. This is reported as
**partially measured**, not as a token-efficiency result.

## Decision

**AI auto-generation: No-Go for production.** Schema validity improved and the
holdout did not collapse, but 5/20 regression scenes were visually unusable or
partial, no learner study was run, and the model still requires one repair on a
substantial minority. It must remain research, not a Tutor feature.

**Production Scene playback: Conditional Go.** Only the reviewed approved scene
is live, behind a default-off flag; it is safe to RC as a playback surface, not
as an auto-generation system.
