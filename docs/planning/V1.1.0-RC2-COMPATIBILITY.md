# DSH 0.2.2-rc.2 Compatibility Audit

## Actual source

- Local `dsh` command points to an old checkout (`0.1.7-alpha.2`), not rc.2.
- Public npm Registry currently exposes `@deepseek-ai/dsh` latest/next 0.2.2-rc.1;
  **rc.2 is not published to npm**.
- The installed desktop app contains `@deepseek-ai/dsh-desktop-runtime`
  **0.2.2-rc.2** inside `Contents/Resources/app.asar`.

Reproducible isolated method:

```bash
npx -y @electron/asar extract \
  '/Applications/DeepSeek Harness.app/Contents/Resources/app.asar' \
  /tmp/dsh-rc2-extract
RC2=/tmp/dsh-rc2-extract/dsh/node_modules/@deepseek-ai/dsh/lib/bin.js
node "$RC2" --version   # 0.2.2-rc.2
DSH_HOME=/tmp/udt-rc2 node "$RC2" --profile e2e \
  --from-default-profile web --dump-config
```

This is an extracted copy of the installed app, not a Registry install.

## Compatible surfaces observed

- Plugin registration and web boot.
- Cordis 4.1 loading.
- Storage domain v1 open/read.
- Tool registration.
- Skill discovery from workspace `.agents/skills`.
- Real model text generation.
- Browser Learning surface boot.
- Image attachment intake and actual-pixel reading.
- No rc.2-specific client exceptions in the tested surfaces.

## New in rc.2 relevant to this project

- Image prompt parts/attachments and image-capable DeepSeek adapter.
- Host image normalization/limits and image file access.
- No observed supported plugin background model-execution service.
- No observed typed teaching events or immersive workspace API.

## Compatibility matrix

| Host | Role |
|---|---|
| DSH 0.2.2-rc.2 | primary development / browser / image E2E |
| DSH 0.2.2-rc.1 | compatibility regression; package build/dev baseline |

Runtime peer ranges already admit rc.2. Build/dev dependencies remain rc.1
because rc.2 is not available from the public Registry; documented, not hidden.
