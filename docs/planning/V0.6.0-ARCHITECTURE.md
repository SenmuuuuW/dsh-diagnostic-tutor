# v0.6.0 architecture — reliable teaching content and real materials

Status: development branch `feat/v0.6.0-learning-materials`, based on the
prepared 0.5.0 release. Not published.

## 1. Why this version

v0.5.0 exposed two product gaps:

1. a real streaming model produced malformed tool JSON when asked to append a
   slider, a step-through and a figure in one call;
2. a learner's own textbook or lecture PDF could not enter the course at all.

v0.6.0 therefore improves **how teaching content is written** and **what
learners can bring**, without changing the teaching/runtime boundary.

## 2. Incremental block protocol

New tool: `udt_lesson_append_block`.

```json
{
  "attemptId": "active-attempt",
  "expectedRevision": 4,
  "block": {
    "id": "figure-matrix-vector",
    "type": "figure",
    "content": { "alt": "...", "svg": "<svg ...>...</svg>" }
  }
}
```

Rules:

- exactly one block per call;
- append at the end, preserving existing order;
- block `id` is the idempotency key;
  - identical retry → `added: false, idempotent: true`, no new unit;
  - same id + different content → `append-block-id-conflict`;
- optional `expectedRevision` is the **course-run revision** from
  `udt_path_get`; a mismatch is refused with the current revision;
- all existing validation remains: `KnownBlockSchema`, host MathML, source
  refs, asset refs, `MAX_BLOCKS_PER_LESSON`, `MAX_LESSON_BYTES`;
- planned attempts still require `attemptId` and a bound node; legacy lessons
  still work without an attempt;
- `udt_lesson_update` remains the full/append/replace API and is unchanged.

Concurrency: `mutateCourseRun` serializes writes per session/run; the append
transform runs against the latest committed lesson. A stale revision is rejected
before any content change.

## 3. PDF sources

- `POST /source/pdf` accepts raw bytes with a filename query/header.
- Extraction is local (`pdfjs-dist` legacy build), no worker fetch, no
  network, no execution, no OCR.
- Limits: 20 MB input, 400 pages, 2,000,000 extracted characters; each page
  capped separately; encrypted/corrupt/oversized PDFs are rejected before a
  source record is written.
- Stored on `sources`: original filename, SHA-256 of original bytes, byte size,
  page count, and `pages[]` with 1-based original page numbers and extracted
  text. The original binary is not copied into `udt.json`.
- `udt_source_get` accepts `pages` and `maxChars`: at most 20 pages / 20k chars
  per call. Model context never receives a whole textbook automatically.
- `sourceRefs` may carry `page` and `pageEnd`; the write boundary verifies the
  page exists in the cited PDF. `locator` remains free text.
- `POST /source/delete` removes the source; the browser materials list exposes it.

## 4. Local image assets

- Separate content-addressed store:
  `<dsh-home>/storages/diagnostic-tutor-assets/<sha-prefix>/<sha256>`;
  metadata is in the additive `assets` table.
- Accepted types are detected from bytes: PNG, JPEG, WebP. Declared MIME and
  filename extension are not trusted. Max 5 MB, 4096×4096 and 16,777,216 pixels;
  max 80 assets.
- `POST /asset` raw upload, `GET /asset?id=` bytes with `nosniff`, sandbox CSP
  and long private cache, `GET /assets`, `POST /asset/delete`,
  `GET /assets/export` (JSON with base64 for local backup) and
  `POST /assets/import`.
- New `image` block: `{ assetId, alt, caption? }`. Remote URLs and filesystem
  paths are rejected by the strict content schema. The renderer builds the local
  asset URL and degrades to a caption if bytes are missing.
- The model can list asset metadata (`udt_asset_list`) and add an explicit local
  path (`udt_asset_add`), but **does not receive pixels**. This is a display
  feature, not multimodal understanding.

## 5. Evidence semantics

- Quiz/flashcard responses are recorded and append at most one neutral
  `practice` evidence per attempt/block; re-submission updates the response and
  does not duplicate evidence.
- A `check` answered in chat is not a block response. The tutor may record a
  `check` observation after actually seeing the answer, using
  `udt_map_update add-evidence` with the active attempt; no automatic scoring.
- Viewing a lesson, moving a slider or finishing Study is presentation state,
  never evidence.
- No runtime auto-advance, auto-mastery or auto-replan is added.

## 6. Study persistence hardening

- `savedAt` is an optional browser clock hint; a save older than the stored
  `updatedAt` by more than 5s is refused as `stale-study-save`.
- `pagehide` / `visibilitychange(hidden)` flush a pending debounced save;
  `saveStudy` uses `keepalive`.
- A restored position still uses block id, step, scroll ratio, fullscreen and
  finished; unknown blocks fall back to the step index.

## 7. Compatibility

- `udt` domain version remains **v1**; `assets` is an additive table and
  `CourseAttempt.study` remains optional.
- Old lessons without `image` open unchanged; an old client degrades the block
  as unknown.
- Old `udt_lesson_update` calls remain valid; the new tool is additive.
- New source fields (`pages`, `pageCount`, `SourceRef.page`) are optional.
- The plugin's installed dependency set gains `pdfjs-dist`; peer DSH packages
  remain peers.
