# v0.11.0 Upgrade Test: 0.4.1 -> 0.11.0

Isolated environment only. No real user profile was touched.

## Procedure

1. Installed public `dsh-diagnostic-tutor@0.4.1` into a fresh DSH profile.
2. Started the 0.4.1 plugin; diagnostics loaded.
3. Seeded a legacy course and diagnosis node through the **0.4.1 state module**
   (not a current-schema fixture):
   - course `legacy-ml` "Legacy ML";
   - nodes `legacy-ml:goal` and `legacy-ml:math`;
   - diagnosis evidence on the math node;
   - session project `session-legacy`.
4. Restarted 0.4.1 and verified `/diagnostics`:
   `courses:1, nodes:2, projects:1`, domain v1.
5. Backed up `storages/` as `storages-before-upgrade`.
6. Installed local 0.11.0 tarball over the same profile and started it.
7. Verified:
   - plugin version 0.11.0;
   - `courses:1, nodes:2, projects:1`;
   - legacy project visible in Learning map ("Legacy ML", "Legacy project");
   - no browser exception.
8. Backup retained for rollback.

## Limitations

- Legacy fixture covered course/node/evidence only; no old lesson, review card,
  asset, or Study progress data.
- Rollback was prepared (storage backup) but not exercised end-to-end by
  reinstalling 0.4.1.
- This is not proof that every 0.4.1 data edge case upgrades. It does prove the
  additive v1 domain and core old data survive the package upgrade.
