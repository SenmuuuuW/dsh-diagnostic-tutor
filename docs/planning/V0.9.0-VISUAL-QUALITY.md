# v0.9.0 Visual Quality Gate

Status: implemented for review and research; it is a **renderability/readability**
gate, not a teaching-quality judge.

## Shared implementation

- [`src/scene/visual-lint.js`](../../src/scene/visual-lint.js)
- [`src/scene/visual-lint.d.ts`](../../src/scene/visual-lint.d.ts)
- CLI: `node scripts/scene-review.mjs lint <candidate.json>`
- Browser review: [`preview/scene-review/`](../../preview/scene-review/)
- Browser frame inspector: [`scripts/scene-visual-inspect.mjs`](../../scripts/scene-visual-inspect.mjs)

The linter is pure data-in/data-out: no DOM, no model, no eval. Production,
research and the review page use the same rules. A research-only `validate`
option lets named-state scenes be inspected without changing the production
schema.

## Rules

| Code | Severity | What it detects |
| --- | --- | --- |
| `VISUAL_MISSING_STROKE` | error | line/arrow with omitted or `none` stroke |
| `VISUAL_INVISIBLE` | error | explicit `fill:none` + no stroke, or opacity ≤ .05 with no revealing state |
| `VISUAL_IMPLICIT_FILL` | warning | closed shape/text omits fill; SVG would default to black |
| `VISUAL_LOW_CONTRAST` | warning | stroke/fill contrast below 1.6:1 against the background |
| `VISUAL_OUT_OF_VIEWPORT` | error/warning | fully outside is error; partial clipping is warning |
| `VISUAL_INVALID_GEOMETRY` | error | zero/negative width, height, radius |
| `VISUAL_INVALID_EXPRESSION` | error | non-finite expression at sampled parameter/time boundary |
| `VISUAL_EXTREME_VALUE` | warning | extreme coordinate or non-finite geometry |
| `VISUAL_TEXT_OVERFLOW` | warning | estimated label wider than viewport |
| `VISUAL_TEXT_OVERLAP` | warning | approximate label boxes overlap |
| `VISUAL_DUPLICATE` | warning | same text at the same position |
| `VISUAL_SCHEMA_INVALID` | error | schema failed before visual checks |

Sampling: time 0/mid/end, every keyframe and checkpoint; each numeric property
at min, default and max. Numeric values are evaluated through the same safe
expression evaluator as the renderer; expressions are never executed as code.

The four math failures are real, not cosmetic: the v2 outputs omitted visible
stroke on the curves/axes. They were already recorded as not-reviewable in the
v0.8 report.

## False positives found and corrected

- Named-state scenes intentionally start some primitives at `opacity:0`, then
  reveal them from a state override. The first linter version called those
  invisible and produced **3 false positives** in v2 CS scenes. It now treats a
  hidden element with a revealing state as a warning, not an error.
- `VISUAL_IMPLICIT_FILL` is a warning because an omitted fill is visible
  (SVG defaults to black); it is not automatically an error. Explicit
  `fill:none` without a stroke remains an error.
- The approved scene is the regression guard: it must remain at 0 errors.

## Browser inspection

`scripts/scene-visual-inspect.mjs` loads a SceneSpec into Scene Lab and records
initial/mid/end/checkpoint and parameter min/mid/max frames. For each frame it
records a screenshot, SVG stage bounds, primitive bounds/visibility, and renderer
exceptions.

Measured:

- approved scene: 6 contexts, 0 exceptions, all expected primitives visible;
- v2 gradient scene: 11 contexts, 0 exceptions, but static gate 11 errors and
  visual output is not reviewable.

## What is still not automated

- semantic/mathematical correctness;
- whether a visual is the right teaching medium;
- label meaning, cultural/contextual ambiguity;
- full visual contrast for gradients, dashed partial elements and overlapping
  non-text shapes;
- named-state animation visual semantics beyond hidden/revealed checks;
- human judgments about cognitive load and accessibility.

These remain manual review items. A green lint is **not** an approval.
