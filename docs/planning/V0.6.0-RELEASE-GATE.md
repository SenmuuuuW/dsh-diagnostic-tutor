### Manual findings

**Attention Is All You Need — usable with caveats.**

- Text is generally in reading order, but figure captions can be emitted before
  the body text on the same page (page 4 starts with the Figure 2 caption).
- Math is partially preserved (`√dk`, `ht−1`, subscripts/superscripts often
  flattened), but spacing and symbols are lossy. It is enough to locate the
  concept, not enough to trust a reconstructed equation.
- Table 3 loses column alignment: rows and values are present but visually
  flattened. A tutor must cite the page and not claim a structured table.
- Fallback: use page text as evidence plus a clear "see original page" citation.

**GPT-3 paper — usable for page selection, not table structure.**

- 75 pages / 237k extracted chars; the page-bounded API is essential.
- Figure captions and body text can interleave on mixed-image pages.
- Tables are flattened into lines; values remain readable but semantics are
  ambiguous.
- Fallback: ask for a specific page range and keep table interpretation out of
  the model unless the source text states it.

**World Models — usable for prose and code.**

- Two-column/layout artifacts exist, but prose paragraphs are mostly intact.
- Figure captions are interleaved with body text.
- Pseudocode blocks survive as text; math notation is partial.
- Fallback: cite page and use the extracted prose, not the figure content.

**Blank pages and scanned pages.**

- The test fixture's blank page is preserved with its original page number and
  empty text; page count is unchanged.
- An image-only PDF produced zero extracted text. The system stores a ready
  source with empty page text and `udt_source_get` explains that no text was
  extracted. **No OCR is implemented**; the UI/docs say scanned pages are not
  OCRed.

### Error handling

- Encrypted PDF → `source-pdf-encrypted`; no source written.
- Corrupt/not-PDF → `source-pdf-invalid` / `source-pdf-unreadable`; no source
  written.
- Over 20 MB / 400 pages / text budget → rejected; no source written.
- Page citation outside the PDF → write refused.
- Extraction failure cannot leave a partial Source because the record is written
  only after complete extraction.

## 4. Image capability boundary

Verified in code, UI and Skill:

- **Image display: implemented.** PNG/JPEG/WebP are stored content-addressed,
  rendered through the local asset route, and can appear in an `image` block.
- **Image understanding: not implemented.** `udt_asset_list` returns metadata
  only; the model receives no pixels. The Course materials UI says so explicitly;
  the Skill contract says not to claim it read an image.

A real-model E2E preserved this boundary: the model created an image block but
stated it had not seen the pixels.

## 6. Release decision

**Pass with documented limitations.**

Gate blockers: none for a local 0.6.0 candidate.

Documented limitations that remain release-visible:

- PDF is text extraction only; scanned pages are empty, no OCR;
- formulas/tables are lossy and must not be presented as structured facts;
- no model image understanding;
- real-model E2E is one model/persona;
- npm publication/tag/push require explicit approval and have not happened.

Local release artifacts may be prepared, but **this branch was not pushed,
tagged, published or installed into the real DSH environment**.
