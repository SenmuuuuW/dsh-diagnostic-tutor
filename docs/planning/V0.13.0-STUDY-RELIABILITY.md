# v0.13.0 Study Reliability: Scene Continuity

## Root cause

`writeCourseTeaching` appends a new attempt unit for each lesson write. The Study
surface used `const activeUnit = units.at(-1)`. `units` is a per-node latest map,
so when the Tutor appended a lesson for a different diagnosis node, the newest
unit became Study's current lesson. The scene was still persisted in the earlier
unit but was no longer the selected unit.

This was a selection bug, not block loss, digest loss, or a client cache drop.

## Fix

`src/client/lesson-units.ts` now picks the unit containing the stored
`attempt.study.blockId` first, and only falls back to the latest unit when Study
has no block id or the stored block no longer exists (explicit replace/delete).

The scene block id stays `scene-<candidateId>`. Append and replace semantics
remain distinct, and a new unit for another node no longer steals the current
Study surface.

## Verification

- Unit tests: stored scene, deleted block, no progress (3 tests).
- Final 0.13 package browser E2E: seeded scene unit; appended a second unit for
  another node; reopening Study still rendered the scene (`svg=1`), not the
  appended read block.
- Controls: Play/Pause/±0.5s/slider executed; time advanced to 1.10s.
- Feature flag off: no SVG, fallback text shown.
- Scene block persisted with stable id.
