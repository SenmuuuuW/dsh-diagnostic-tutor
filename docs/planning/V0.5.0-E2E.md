# v0.5.0 real-model end-to-end run

Date: 2026-11-05. This was a real DSH Agent + real installed Skill + real model
run, not a fixture or a mock. It used an isolated DSH home and never touched the
learner's real `~/.dsh` storage.

## Environment

- DSH `0.2.2-rc.1`, web profile created from the default web profile, isolated
  `DSH_HOME=/tmp/udt-e2e-live`.
- Plugin loaded from this source checkout through a `link:` dependency.
- Skill: the working copy of `universal-diagnostic-tutor` from
  `skills/universal-diagnostic-tutor`, symlinked into the isolated DSH skill root.
- Model: DeepSeek-V4.1-Flash as shown by the running app; the host had real
  account credentials copied into the isolated home.
- GUI driven over CDP in headless Chrome. No storage JSON was edited by hand.

## Flow and observations

1. **Goal + diagnosis.** The real model loaded the Skill, called
   `udt_goal_create`, wrote a GoalBrief, then asked one diagnostic question.
   After the answer it called `udt_map_update`, `udt_decide_next` and
   `udt_path_update` with an assessment (`status: ready`), then proposed a
   complete route.
2. **Route.** 4 modules, 8 lessons, accepted from the Course preview UI as
   route v1. The UI showed the accepted modules and "0/8 lessons completed".
3. **Lesson generation.** The model read
   `references/lesson_block_contract.md` and wrote a nine-block lesson:
   `text, example, formula, check, slider, step-through, figure, quiz, flashcard`.
   The Figure block rendered a sanitized inline SVG; the Slider moved from
   `x = 2, f(x) = 4` to `x = 3.20, f(x) = 10.24`; Step-through moved `1 / 3` to
   `2 / 3`; all rendered in the focused Study surface.
4. **Answers + evidence.** The quiz answer was recorded through
   `POST /path/answer` as a `quiz` response. The flashcard self-report was
   recorded as `again`. The attempt showed **2 practice responses** and the
   runtime evidence count was **5** (2 check, 2 practice, 1 goal-stated), with no
   mastery claim.
5. **Review.** The flashcard produced one due review card. Review UI showed the
   card and its back; grading `good` produced a review log entry and rescheduled
   it to the next day. Insights then showed the recent review and the attempt.
6. **Persistence.** Study auto-saved its position without an explicit exit. After
   a full browser reload, "Continue learning" restored **Step 6 of 9** instead of
   Step 1. Re-opening Study did not call the tutor, re-submit a quiz, advance the
   route or overwrite evidence. The saved state includes block id, step index,
   scroll ratio, full-screen preference and finished flag.

## Tool-input reliability

- `udt_lesson_update` succeeded with the initial 4 text/example/formula/check
  blocks.
- One combined append of slider + step-through + figure failed in the real
  streaming model path with `MALFORMED_RESPONSE` ("tool input is invalid JSON").
  This was a model/tool-input failure, not a runtime validation failure.
- Recovery: split the write into small calls. Five separate one-block append
  calls succeeded (`slider`, `step-through`, `figure`, `quiz`, `flashcard`).
- Skill Contract now recommends one complex block per call. This is a delivery
  rule; the schema itself is unchanged.

## Limitations

- One synthetic learner persona and one model, not a user study; teaching value
  still needs real learners.
- The `check` block is an invitation to answer in chat; the recorded answer in
  this run came from the separate `quiz` block. This is the intended boundary,
  but it means a "check" alone does not create an evidence record.
- Headless browser; visual/pixel quality and scroll-position restoration were
  structurally checked, not judged by a human.
- The run is scripted for repeatability but is not part of `pnpm test`; CI has
  no real model credentials.
