# v0.6.0 real-model end-to-end run

Date: 2026-11-06. This was a real DSH Agent + real installed Skill + real
DeepSeek-V4.1-Flash run against isolated storage, not a fixture or mocked model.

## Environment

- DSH `0.2.2-rc.1`, isolated `DSH_HOME=/tmp/udt-v06-live`; web profile.
- Plugin loaded from this source checkout through a `link:` dependency.
- Skill: working copy of `universal-diagnostic-tutor` (v0.6 contract) symlinked
  into the isolated skill root.
- GUI driven over CDP; no storage JSON was edited by hand.
- Temporary credentials, profile and browser data were deleted after the run.
  The learner's real `~/.dsh` was untouched.

## Materials

A real PDF fixture (3 pages, one empty page) and a 32×24 PNG were placed in the
repo test fixtures. The model was asked to add both with its runtime tools.

Observed:

- `udt_source_add kind=pdf` created source `90f15203…` with `pageCount: 3`,
  three page records, original SHA-256 and byte count; page 1 was read with
  `udt_source_get pages=[1]`.
- `udt_asset_add` created asset `925de9e0…`, `image/png`, 32×24, 109 bytes.
- `udt_asset_list` returned metadata only. The model explicitly said it had not
  seen the image pixels.
- The generated formula block cites the PDF with:
  `sourceRefs: [{sourceId: "90f15203…", locator: "p. 1 — the negative gradient and the update", page: 1}]`.

## Learning loop

1. Goal `Gradient Descent (Exam Prep)` and one diagnostic answer (w₁ = 2.4).
2. Assessment recorded `ready`, 4-lesson route proposed and accepted.
3. First lesson completed with real check evidence.
4. Second lesson (L2) kept working while incremental writes were appended.
5. Seven L2 blocks rendered in Study:
   `text, formula, example, check, figure, image, quiz`.
6. Figure SVG rendered (one `.dt-figure-canvas svg`).
7. Image block rendered through `/diagnostic-tutor/api/asset?id=…`, with
   `naturalWidth=32`, `naturalHeight=24`, alt text and caption.
8. A quiz answer was recorded through the Study UI:
   `l2-quiz-1` / `It moved opposite the gradient computed at the old point.`
9. Runtime recorded one practice evidence for that attempt; Insights showed
   **5 evidence** (`check: 3`, `practice: 1`, `goal-stated: 1`) and one due review
   card from the L1 flashcard. The attempt remained `working`; no auto-advance.
10. L2 Study progress was saved (`stepIndex: 6`, `finished: true`) and restored
    after reopening/refresh.

## Incremental write observations

- `udt_lesson_append_block` successfully appended:
  - a check and PDF-cited formula to L1;
  - a complex SVG figure to L2;
  - an image block with a local asset and page citation;
  - a quiz block.
- One attempt to append a figure with too-long alt text was refused with
  `append-invalid-block: content.alt: Too big...`; the model shortened the alt
  text and retried **with the same block id**, which succeeded. No partial block
  was written.
- A write against the already-completed L1 attempt was refused
  `stale-attempt`; no content changed. This is the intended boundary, not a
  regression.
- No full-lesson resend was needed for any of the successful appends.

## Limits

- The model needs the asset id from `udt_asset_list` (or the UI) before writing
  an image block.
- The model cannot see raster pixels in this build; the UI must not claim it can.
- PDF extraction is text-only and the fixture's page 2 is blank; no OCR exists.
- The run used a tool-path PDF import plus the tested UI upload route, not a
  human clicking the file picker for this exact model turn.
- Only one model/persona; teaching-value evaluation is still a separate study.
