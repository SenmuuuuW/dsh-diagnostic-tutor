# v0.10.0 Canonical Contract & Structured Repair

## Contract

- Canonical module: [`src/scene/contract.js`](../../src/scene/contract.js)
- Generator contract: **v4**; SceneSpec version: **0.1**; research schema: **0.1.1**
- Official optional fields: `properties` (omit or `[]`), `metadata.topic`.
- Deprecated alias: `textAnchor` -> `anchor`; accepted only by explicit
  normalization, never by strict validation.
- Research-only: `states`, `stateTimeline`; production validator rejects them.

Prompt output is derived from `contractSummary()` (top-level fields, metadata,
primitive fields, exact property/timeline/control/checkpoint/accessibility/
sourceRefs examples), not from a separate hand-maintained field list.

## Three outcomes

| Phase | Meaning | v4 sealed result |
| --- | --- | ---: |
| Raw strict | model output as written | **0/11 scenes** |
| Normalized | explicit alias normalization only | **0/11** |
| Deterministically repaired | recorded contract-drift/style fixes | **11/11** |
| Model repaired | separate semantic repair test | **1/1** |

Strict success is never reported as normalized or repaired success.

## Structured error contract

Every error carries: `category`, `code`, `severity`, `path`, `primitiveId`,
`expected`, `actual`, `explanation`, `suggestedRepair`.

## Repair engine

- Attempt ID: SHA-256-derived from case/candidate/input/contract.
- Input/output SHA-256 hashes.
- Raw and every repair round retained.
- Deterministic fixes are explicit; they never change a mathematical
  relationship:
  - textAnchor -> anchor (normalization, not repair);
  - `properties[].value` -> `default`;
  - timeline target `field` -> `property`;
  - checkpoints prompt/id/title/pause canonicalization;
  - controls `property` -> `propertyId`;
  - sourceRefs bare strings removed;
  - bare numeric expression strings wrapped in `{expr}`;
  - `**` -> `^` (same mathematical intent, canonical grammar);
  - accessibility alt truncation and reducedMotion canonicalization;
  - invalid tracks with no primitive target removed.
- No fix for unknown variables, invalid geometry, out-of-viewport content,
  or semantic contradictions.

## v4 observed contract drift

Despite exact prompt examples, the model still emitted `value` instead of
`default`, `field` instead of `property`, `prompt` instead of checkpoint body,
bare expression strings, `**` powers, invalid tracks, and long alt text.
That is the root cause of **0/11 strict first pass**. The deterministic repairs
fixed shape, but this is not evidence that the model learned the contract.

## Safety

- No model JavaScript/HTML/URLs accepted.
- Repairs re-run schema, visual and supported semantic checks.
- Repair never auto-approves; local human CLI remains the boundary.
- Final content changes produce new hashes/digests.
