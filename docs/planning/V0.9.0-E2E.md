# v0.9.0 Real DSH E2E — final package

Environment: isolated `DSH_HOME=/tmp/udt-v09-e2e`, DSH `0.2.2-rc.1`,
`dsh-diagnostic-tutor-0.9.0.tgz` installed in profile `e2e`, feature flag
`DSH_DIAGNOSTIC_TUTOR_DYNAMIC_SCENES=1`, local registry containing one extra
locally reviewed variant. The real user `~/.dsh` was not modified.

The lesson fixture was seeded through validated state APIs solely to arrange the
browser test. It is not model-generated content and it is not an approval bypass.

1. Opened DSH, Learning map → Continue learning.

   SVG rendered with circle, radius, dashed sine height, point, sine curve,
   narration and checkpoint.

   narration changed to “At pi, the sine height is zero.”

   `scenes['scene-unit'] = {time:3.14, params:{angle:2}, playing:false, checkpointId? not required}`;
   attempt evidence array was `[]`.
6. Reloaded the page, reopened Learning map → Continue learning. Scene restored
   at **3.14s**, angle **2.00rad**, and the control showed **play** (paused), not
   autoplaying.
7. Pressed **Continue**. Study moved to **Step 2 of 2, Read**; the following
   text block appeared. No evidence or mastery was created.
8. `GET /scene-config` returned approved code scene plus
   `local-reviewed-unit` while flag was on. No browser exceptions.

## Evidence boundary

- Scene progress is presentation state only.
- `evidence: []` before/after scene interaction.
- Continue is a learner action; playback never auto-advanced the lesson.
- The local registry only affects which reviewed content may render; it cannot
  write evidence or complete a lesson.

## Limitations

- Tested one seeded approved scene, not a content library.
- The browser session started with no model credential, so the tutor turn failed;
  the scene surface itself was exercised from seeded validated content.
- No human learner took part.
