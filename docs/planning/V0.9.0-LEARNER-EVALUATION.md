# v0.9.0 Learner evaluation status

**No learner study was run in v0.9.** No result is inferred from the visual
review, the model benchmark, or the developer E2E.

## Ready-to-run protocol

Conditions, balanced order:

A. static explanation;
B. same objective with the approved interactive scene.

Session:

1. pre-check (prior knowledge + misconception);
2. 8–12 minute activity, think-aloud, no tutor coaching;
3. post-check (explain the mechanism + near transfer);
4. unseen transfer problem;
5. 4-item feedback: clarity, cognitive load, confidence, continue-interest.

Measures:

- normalized individual gain (descriptive with small n);
- transfer rubric 0–3, two raters, disagreements retained;
- control discovery/errors (play, seek, slider, checkpoint);
- keyboard-only and reduced-motion runs;
- short interview: what changed, what the animation made clearer or misleading.

Target n=8–12 university-level volunteers, anonymous IDs, consent, no personal
data in repository. This is usability/learning signal, not a powered efficacy
trial. Negative cases must be reported.

## Why not run here

No volunteers were available in this environment. Simulating learners with a
model would not be a learner evaluation and is explicitly not counted.

## What the engineering tests do and do not establish

They establish schema safety, visual readability gates, playback, persistence,
flag fallback, approval boundaries and browser behavior. They do **not**
establish learning gain.
