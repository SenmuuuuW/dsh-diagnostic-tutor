# v0.7.0 SceneSpec v0 — declarative teaching scenes

Status: research only. No production `scene` block, no production Study change,
and no plugin bundle import. The runtime code remains under
`research/dynamic-lesson-engine/`; the browser lab is under `preview/scene-lab/`.

## Architecture

```
Teaching request
    ↓
model-authored SceneSpec JSON
    ↓
schema validation (structure, limits, IDs)
    ↓
semantic validation (targets, expressions, timestamps, accessibility)
    ↓
safe SVG interpreter (deterministic time, DOM construction, textContent)
    ↓
browser Scene Lab (play/pause/seek/step/controls/checkpoints/fallback)
```

No model code is executed. The renderer uses only SVG elements created with
`createElementNS`, attributes from a bounded set, and `textContent`.

## Schema v0.1

Top-level keys:

| Key | Purpose |
| --- | --- |
| `version` | `"0.1"` |
| `viewport` | bounded width 240–1600, height 180–1000, optional background |
| `metadata` | title, subject, objective, learner, misconceptions, expected understanding |
| `properties` | ≤8 numeric slider definitions (min/max/step/default/label/unit) |
| `primitives` | 1–120 `rect`, `circle`, `line`, `path`, `text`, `arrow` |
| `timeline` | duration 0.5–120s; ≤80 tracks; 2–100 keyframes per track; ≤800 total |
| `controls` | optional slider declarations bound to a property |
| `checkpoints` | ≤12 timed teaching pauses with title/body/pause/learnerAction |
| `narration` | ≤20 timed cues |
| `fallback` | required static text description |
| `accessibility` | alt, reducedMotion, keyboard |
| `sourceRefs` | optional citations (≤6) |

Numeric fields are a finite number or `{ "expr": "..." }`. Expressions use
only declared property IDs plus `t` and `duration`; operators and functions:
`+ - * / ^ ( )`, `sin cos tan sqrt abs exp log ln floor ceil round pow min max`,
`pi`, `e`. Maximum 240 characters, maximum depth 64, finite results only.

Timeline tracks target a **primitive numeric property** (for example
`{ primitive: "point", property: "cy" }`) and interpolate keyframes `at` /
`value` with `linear|ease-in|ease-out|ease-in-out|step`.

Checkpoints may pause playback; scene narration and checkpoint text are
content-embedded cues. The learner can resume, seek, step, or change a parameter.

## Expressiveness

The v0 prototype can build:

- axes, curves, tangent/rise-run triangles, unit circles, vectors and arrows;
- parameterized diagrams whose shapes depend on sliders;
- keyframed motion and easing;
- staged narration and checkpoints;
- static fallback descriptions and accessible labels;
- local, self-contained scenes with no external resources.

It deliberately cannot represent:

- arbitrary JavaScript/HTML/CSS or remote scripts/assets;
- 3D, WebGL, canvas, video, GIF, image understanding;
- rich math typesetting (labels are plain text, not TeX/MathML in this spike);
- general algorithm state machines with structured state (the CS cases were
  rewritten into explicit primitive scenes with explanatory text);
- data-backed tables, network requests, live tutor synchronization, or
  multi-scene orchestration;
- infinite/looping animation or unbounded expression evaluation.

## Safety model

- strict unknown-key rejection at every object;
- bounded primitive/track/keyframe/checkpoint/narration counts;
- IDs restricted to letters/digits/underscore/hyphen; no property access;
- SVG path data restricted to path commands/numbers (no tags/URLs);
- colors restricted to hex/rgb/hsl/basic names; no `url()`, `var()`, CSS blocks;
- text rendered via `textContent`, never `innerHTML`;
- no `href`, `foreignObject`, event-handler attributes, `onclick`, or external
  resource fields in the schema;
- expression parser is an allowlisted arithmetic language, not `eval`/`Function`;
- timeline is finite; no loop field;
- validation before render and a static fallback on renderer errors.

## Compatibility and schema revisions

The benchmark exposed schema ergonomics that were revised transparently:

1. IDs may start with a digit (`^[A-Za-z0-9_][A-Za-z0-9_-]{0,63}$`); they are
   map/attribute keys, not executable identifiers.
2. Expression identifiers are case-insensitive, matching how the model writes
   `demandShift`/`demandshift` inconsistently.
3. `reducedMotion` accepts the documented strings and the boolean compatibility
   alias (`true → static`, `false → no-autoplay`).
4. Controls accept the compact `{id,kind,propertyId}` form and the observed
   `{type:"slider",target,...}` alias, normalized to the same property-bound
   control.
5. Missing checkpoint IDs get stable per-array IDs and missing `pause` defaults
   to `false`.
6. `rect.rx` and `text.fontSize` are optional with defaults 0 and 16.

These are validator compatibility rules, not edits to model output. Raw
attempts are preserved under `research/dynamic-lesson-engine/benchmark/generated/`.
The benchmark reports both the strict original first-pass count and the
post-revision first-pass count.

## Renderer and Scene Lab

`SceneRenderer` exposes `play()`, `pause()`, `replay()`, `seek(time)`,
`step(delta)`, `setProperty(id,value)`, and a destroy path. It is deterministic:
seeking to the same time twice yields the same SVG attributes; no time is
implicit except the user-initiated play loop. The scene lab supports JSON
loading, validation errors, playback, replay, timeline seek, step forward/back,
parameter controls, checkpoint jumps, narration, metrics, keyboard controls,
and reduced-motion fallback.

## Known limitations

- SVG/WAAPI prototype uses manual interpolation rather than WAAPI; seek is
  deterministic and no animation is committed to the document timeline.
- No symbol/column/table layout engine; generated labels can overlap.
- No scene-level formula renderer; mathematical notation is plain text.
- No automatic semantic correctness checker: the benchmark's correctness is a
  manual review, not a formal proof.
- SceneSpec is not yet a Lesson Block; it must not be passed to
  `udt_lesson_update`.
